# 算法卡片开发规范

## 算法学习卡片

以下规则适用于本项目中的算法学习卡片。当用户要求根据代码或力扣题目新增、修改或完善算法卡片时，默认执行这些规则，无需让用户重复提供。其他博客功能不必套用本节要求。用户在当前对话中的具体要求优先。

默认直接实现通过上一步、下一步及拖动进度条查看的交互式可视化，不先询问是否需要动画。使用中文，重点帮助读者看懂执行过程，不只提供静态图或文字解释。

如果用户提供代码，以该代码为基础展示；如果只提供题目，默认使用清晰、适合学习的 Python 解法。若代码有问题，先指出，并明确区分原代码的实际行为和修正后的行为，不能默默修改后只展示正确结果。

### 样本

- 提供多个可切换的例子，覆盖典型情况、不同判断分支和边界情况，必要时加入极端情况。
- 每个例子附一句简短说明，告诉读者主要观察什么。
- 优先用少量数据展示完整过程。极端情况可以通过特殊数值或排列体现，不必使用大量元素。
- 题目样本遵守原题约束；用于展示代码问题的反例单独标明。
- 大规模压力输入用于开发验证，不默认放入教学样本选择器。
- 切换例子时同步重置到新例子的初始状态。

### 动画

- 简洁、干净，配色丰富但克制，颜色有固定含义。
- 当前处理、正在比较、已经完成和最终答案等状态容易区分，配合箭头、边框或简短标签，不只靠颜色区分。
- 动画区主要展示数据结构和当前操作，不堆放变量名和变量值。保留理解画面必需的下标、指针位置、节点值；关键变量集中放在状态监控区。
- 严格对应代码实际执行顺序，展示必要的判断、更新、循环、递归进入、返回和回退，不跳过影响理解的中间变化。
- 每次单步推进对应一个明确的执行步骤。
- 动态规划展示 DP 表、当前更新位置、依赖状态及更新前后的值。
- 双指针或滑动窗口展示指针位置、窗口范围及移动过程。
- 哈希表展示查询、插入和匹配过程。
- 树、图或回溯展示访问路径、当前节点及必要的递归或回退过程。
- 其他算法选择对应的直观展示方式，不强行套用两数之和的画面。
- 进度栏永远只保留上一步、下一步和拖动进度条，禁止添加播放、暂停、自动播放、重置及速度控制；不得改动其布局、样式和按钮顺序。单步查看时画面清晰稳定。
- 动效短而克制，不添加与算法无关的装饰。
- 数据较多时展示当前相关部分，明确标记省略内容，保证当前操作对象和答案仍然可见。

### 代码

- 展示与动画对应的完整、可使用的代码，使用清晰的变量命名和常见写法。
- 添加少量简单中文注释，解释关键思路和容易误解的地方，优先解释为什么这样做，不逐行重复代码含义。
- 高亮当前执行行，与动画和状态监控同步，未执行的分支不能表现为已执行。
- 一行代码包含多个重要操作时，可以拆成多个动画步骤，同时保持该行高亮。
- 多语言版本的执行行映射分别维护，不能直接套用同一组行号。
- 复用项目已有的语言切换、复制和展开功能。

### 状态监控

- 只监控理解算法最重要的变量和核心数据结构，不展示全部变量。
- 变量较多时做取舍：核心变量固定展示，辅助变量仅在相关步骤出现。
- 变量名与代码一致，必要时附上简短中文含义。
- 变量发生变化时适度突出，让读者看出这一步改变了什么。
- 尚未赋值与值为 0、空列表、空字典等状态明确区分。
- 数据结构较大时展示与当前操作相关部分，并标明省略。
- 每一步保存独立状态，查看之前的步骤时还原当时的真实状态，不受后续修改影响。

### 同步与验证

- 样本、动画、代码高亮、步骤说明和状态监控展示同一个执行时刻。
- 每一步用一句简短中文说明当前操作及其原因。
- 执行结束后明确展示最终结果；没有找到答案或发生错误时，也展示实际结束状态。
- 验证算法结果、关键判断分支和边界情况，检查动画轨迹与代码行为一致。
- 检查浏览器中的样本切换归零、前后步进、拖动进度条和代码高亮。未完成的检查如实说明。

### 项目复用入口

开发前阅读 `docs/mdx-components.md` 和现有两数之和实现，核实当前代码，复用已有外观和公共操作组件。

- `public/algorithm-cards/problems/1.js`：两数之和的样例、执行轨迹和动画。
- `public/algorithm-cards/shared/card-ui.js`：公共卡片布局及交互。
- `public/algorithm-cards/algorithm-card.js`：按题号加载卡片。
- `src/components/algorithms/AlgorithmCard.astro`：文章中的卡片包装与代码资源。
- `scripts/build-algorithm-code.mjs`：代码展示资源生成。
- `tests/algorithm-card.test.mjs`：现有算法和轨迹验证参考。

新增题目时补齐题目登记、代码资源和文章引用。复杂度等题目属性按实际算法配置，不照搬两数之和的值。已有实现与本规范不一致时，按用户请求范围完善，不自动批量重写所有题目。
