# 代码块设计对照

## 当前交互：双击展开

两数之和卡片的代码区域使用双击切换最大化：首次双击占满卡片阅读区域，再次双击还原；移入和移出鼠标均不改变展开状态。Esc、切换动画或收起解答也会还原。

代码块右上角保留展开／收起与复制两个经典图标、语言选择、语法高亮和行号，沿用 Markdown 围栏的代码外观。展开按钮与双击共享同一状态，再次点击即可收起。复制按钮复制当前语言的完整源码，并短暂显示成功或失败状态；点击复制不改变展开状态。以下内容记录此前设计过程，其中悬浮展开和固定展开按钮已由上述交互替代。

参考：[Fuwari 官方示例](https://fuwari.vercel.app/posts/expressive-code/)、[Expressive Code 外框文档](https://expressive-code.com/key-features/frames/)。以下审美判断来自示例截图与本项目代码的对照；本轮内置浏览器连接超时，未完成新版页面的视觉验收。

## 示例为什么协调

代码块的主体是大块安静的深色背景。行号、分隔线和工具按钮降低对比度，代码文字保持清晰，语法颜色区分内容而不是装饰整块面板。主题色只用于小标签、交互和重要状态。

普通代码没有单独的大工具栏；有文件名时才出现编辑器标签，终端命令才出现终端顶栏。外框表达内容类型，而不是给每段代码增加相同的装饰。

文章卡片、侧栏、标签和代码块使用一致的圆角与间距。边界主要由背景层次区分，阴影和描边很轻。读者先看到正文和代码，再看到辅助操作。

## 我们之前的问题

| 对照点 | 原先卡片的问题 | 这次处理 |
| --- | --- | --- |
| 视觉层次 | 卡片、代码工具栏、状态、变量盒子都有边框或明显底色，层次过密 | 代码减少描边；状态采用方案 A；工具按钮收在右上角 |
| 文字尺度 | 旧模板、主题覆盖和新版样式分别指定字号、行高与内边距 | 正文和卡片共享 14px 字号、24px 行高与同一字体 |
| 代码布局 | 手写行号与 Shiki 高亮只模仿外观，折行和缩进独立实现 | 直接生成 Expressive Code 的行号、折行和缩进结构 |
| 工具操作 | 宽语言下拉框和整条工具栏抢占首行注意力 | 小型语言标签；复制和固定展开保持轻巧 |
| 颜色 | 代码使用单独的灰色和强调色，与博客主题存在差异 | 共用黑色背景与 GitHub Dark 高亮；交互沿用博客主题色 |
| 一致性 | 正文和动态卡片由两套代码块样式维护 | 公共配置集中到 `src/config/code-style.mjs` |

此前反复追加 CSS 覆盖也使实现难以维护：同一选择器在基础模板与主题中重复出现，修改一个局部很容易破坏另一个局部。这次让代码布局交给 Expressive Code，卡片仅处理语言选择、执行行和悬浮展开。旧的 329 卡片仍保留原实现，后续迁移时再处理其样式。

## 后续设计准则

- 以代码和算法状态为主，装饰的对比度低于内容。
- 用留白与对齐建立分组，只在需要区分内容时加边界。
- 同一种角色只使用一套字体、间距和颜色规则。
- 普通代码、文件代码和终端使用符合内容的外框。
- 控件能被发现，同时不占用主要阅读空间；触屏操作保持可见。
- 实际检查深浅主题、窄屏、长代码、菜单与展开状态后再确认完成。
- 代码框内的滚轮只滚动代码；代码滚到末尾后继续滚动页面，不把读者困在代码框内。

## 本次落地与验证

四种语言在构建期间通过 Expressive Code 渲染，浏览器只加载生成的 HTML、CSS 与交互代码。生成 CSS 的主题变量适配 Shadow DOM 的 `:host`，每张卡片独立切换语言、复制完整代码及高亮当前执行行。

正文的 Markdown/MDX 围栏继续使用 Astro Expressive Code，并恢复其原生复制按钮。草稿 `src/content/posts/code-block-preview.mdx` 并列展示普通代码、文件标题与行标记、终端、算法卡片，方便在同一页对照。该草稿不会出现在正式构建的文章列表中。

算法边界与压力测试共 6 项、类型检查和生产构建通过；四种语言的渲染内容与原始代码逐行一致，执行阶段对应的行号均有效，Shadow DOM 主题变量也已核查。开发预览返回 HTTP 200，并包含实际 Expressive Code 结构。内置浏览器持续超时，因此本轮不将视觉与悬浮交互标为已验收。
