# 博客改进需求规格

本规格由当前讨论及原型选择整理，不代表开始实现、拆分任务、派发或部署的授权。

## Problem Statement｜问题陈述

博客目前包含 LeetCode 专题及多种教程、笔记、演示文章，分散了当前算法学习的重点。用户希望暂时只展示 LeetCode 内容，同时保留其他文章以便恢复。

顶栏缺少音乐入口。用户希望学习时可以使用一个小巧、与博客融为一体的音乐浮窗：突出封面和当前歌曲，直接滚动选歌，不需要复杂的播放器控制面板。

算法解答较长，阅读到底部时缺少不占额外空间的收起入口。状态栏原有单击切样本和 Shift+Tab 操作不符合用户希望的交互。

动画外框及内部元素会随步骤内容改变尺寸，影响观察和操作。在杨辉三角五行样本中，原始画布从初始约 138px 增长到第 24 步约 450px，确认存在内容增长引起的布局变化。

## Solution｜解决方案

### 已确认的范围与选择

| 项目 | 最终决定 |
| --- | --- |
| 默认主题色 | 取消修改，保留现有配置和个人选择行为 |
| 文章内容 | LeetCode 以外的文章全部暂时隐藏，保留源文件 |
| 音乐 | 采用最终 C：紧凑左右融合封面卡片 |
| 收起解答 | 采用 B：原有紫色题间分隔线悬停变细、点击收起 |
| 切换样本 | 双击解答顶部状态栏，替换单击切换及 Shift+Tab |
| 动画稳定性 | 采用 B：按当前样本最大展示结构预留完整空间 |

以上字母分别属于不同轮次的原型选择，不是同一组统一方案编号。

### 1. 聚焦 LeetCode 内容

- 保留目前的 17 篇 Hot 100 专题；不删除其文章、题目、题卡或路由。
- 其他文章暂时隐藏，保留正文、元数据和关联资源。
- 首页、归档、分类、标签、文章跳转、RSS、站点地图和搜索应统一反映隐藏状态，不继续列出隐藏文章或由其单独产生的分类和标签。
- 隐藏文章不继续通过文章详情路由公开正文；开发与生产展示范围一致。
- “关于”等独立页面不属于本次隐藏文章范围。
- 后续恢复文章应通过简单、可逆的内容状态或过滤配置完成。

### 2. 顶栏音乐与最终 C 浮窗

**入口与状态**

- 音乐入口位于搜索与调色板之间，沿用博客原生图标家族与按钮风格。
- 按钮操作区与相邻控件同高、同排，采用约 2.75rem 的方形占位及圆润边角；图标采用约 1.75rem 的圆角播放／停止图形。
- 未播放显示播放图标；播放中显示停止图标，名称与提示同步。
- 桌面悬停入口展开浮窗，鼠标进入浮窗可继续选歌；离开后关闭，关闭浮窗不停止音频。
- 点击顶栏入口切换播放与停止。停止以暂停音频、保留进度的方式执行，再次开始从当前位置继续；换歌归零。
- 换页时维持当前歌曲、进度和播放状态；默认不自动播放。

**布局与外观**

- 桌面外框以最终原型约 360×222px 为基准，保持小巧；实际尺寸计算包含内边距与边框。
- 左侧占比大于早期分栏设计，封面铺满左侧并向右渐隐，与歌单共享一个背景，无左右独立卡片或明显分割线。
- 左下方歌名与作者上下排列；歌名约 18px，作者约 11px，保持可读对比度。
- 右侧只显示歌名，约 16px；不显示作者、缩略封面、编号、时长或播放小点。
- 当前播放歌曲以博客主题色突出。滚动中心歌曲最清楚，远处歌曲适度缩小、淡出，可保留最终 C 的轻透视效果。
- 图片与渐隐背景不能妨碍文字及进度条阅读；长标题允许自然截断并提供完整名称提示。
- 跟随博客深浅色和主题色；较窄屏幕内不溢出视口。

**歌单与音乐进度**

- 歌单直接展示在卡片里，不再增加“选歌”按钮、折叠菜单或二级页面。
- 曲目增多时在固定区域内部滚动，不撑高浮窗；首尾歌曲均可居中。
- 滚动改变浏览焦点，点击歌曲才切换播放；点击后将当前歌曲平滑居中。
- 歌单可以使用键盘浏览和选择；减少动态效果设置下取消非必要缩放、倾斜及平滑运动。
- 音乐进度条约 6px 厚，圆角轨道、约 12px 拖动圆点；已播放段浅紫色，剩余段半透明。
- 只显示左侧当前时间，右侧不显示总时长占位符或额外线条。
- 拖动更新真实音频播放位置，切歌后进度归零；尚无有效音频时不伪造时长或播放成功。
- 浮窗不添加音量、上一首、下一首、额外播放键、歌词或其他控制区。

**歌曲资源**

- 展示示例为 battlecry、aruarian dance、四季ノ唄、who’s theme。
- 原型封面使用项目现有图片占位；正式歌曲地址和对应封面由用户后续提供。
- 歌单配置应可替换曲目、作者、封面和音频地址，无须修改播放器主体。
- 缺少音频时可呈现歌曲信息，但不可把演示状态冒充真实播放。完整音频验收依赖有效资源到位。

### 3. 分隔线收起解答

- 使用每道题解答后的现有紫色题间分隔线，不增加额外文字按钮、箭头或一行布局。
- 解答展开时，分隔线悬停或键盘聚焦后从粗线变细线；围绕线中心缩放，不挤动上下内容。
- 提供适度扩大的透明命中区域，避免只能点击几像素细线；区域不可覆盖进度栏或下一题内容。
- 点击、Enter 或空格收起本题解答；焦点返回本题展开入口，视口回到本题，避免跳向下一题。
- 解答已收起时恢复普通题目分隔线，不继续作为收起按钮。
- 只影响所属题卡，多卡片同时展开时保持独立。
- 收起需复用既有动作，使代码最大化和其他临时显示状态同步恢复。

### 4. 状态栏双击切换样本

- 双击目标仅为解答执行终端顶部的状态栏，不扩展到整个解答、动画或代码正文。
- 双击循环切换到下一示例，末尾回到第一示例；步骤、输出、变量监控及代码高亮归零并同步到新样本。
- 取消状态栏样本名称的单击切换，避免双击触发两次切换。
- 去掉 Shift+Tab 文字提示、快捷键声明及拦截，恢复正常反向焦点导航。
- 状态栏不提供最大化；代码正文原有的双击最大化独立保留。
- 样本入口仍可聚焦，Enter／空格切换；输入控件的键盘行为保持正常。

### 5. 按样本预留稳定动画空间

- 在同一样本、同一视口与同一布局模式下，动画外框尺寸在前后步进和拖动进度时保持稳定。
- 固定格子、节点、字体和必要标签的尺寸或占位，避免短长数值、标签出现、结构增大导致无关缩放与重新居中。
- 预留该样本全过程所需的最大展示范围，允许执行前期存在留白。
- 结构锚点保持稳定；算法本身需要的节点移动、指针移动、插入或删除仍按轨迹表现，不把必要运动冻结。
- 切换样本或视口尺寸改变时可以重新确定展示空间；不因普通步进重复调整外框。
- 不能统一写死为原型测得的 528px；数组、矩阵、树、链表、图等按各自共享渲染能力确定边界。
- 继续沿用原算法、样本和快照，代码高亮、说明、变量、结果与执行顺序不变。
- 现有大输入的相关窗口与省略机制保留，不为全部输入生成巨型画布。

## User Stories｜用户故事

1. 作为学习者，我希望首页只展示 LeetCode 文章，以便集中学习算法。
2. 作为博客维护者，我希望其他文章保留源内容，以便以后恢复。
3. 作为访客，我希望归档、分类、标签、搜索和订阅内容一致，以免再次遇到暂时隐藏的文章。
4. 作为维护者，我希望 LeetCode 专题和已有链接继续可用，以免学习入口失效。
5. 作为访客，我希望独立的关于页面继续可用，以便了解博客作者。
6. 作为学习者，我希望音乐按钮位于搜索和调色板之间，以便快速找到。
7. 作为访客，我希望图标能表示播放与停止状态，以便知道点击会执行什么操作。
8. 作为学习者，我希望悬停即可看到音乐浮窗，以便选歌时不离开文章。
9. 作为学习者，我希望浮窗小巧且与博客风格一致，以免遮挡过多学习内容。
10. 作为听众，我希望封面和当前歌曲突出，以便快速确认正在听什么。
11. 作为听众，我希望歌单只展示歌名，以减少阅读负担。
12. 作为听众，我希望直接点击歌曲播放，以免进入额外菜单。
13. 作为听众，我希望长歌单在浮窗内滚动，以免面板越来越高。
14. 作为听众，我希望滚动中心更清晰、远处适度淡出，以便找到想选的歌曲。
15. 作为听众，我希望浏览歌单不会自动换歌，以免误操作。
16. 作为听众，我希望当前歌曲仍有明确标记，以区分播放状态与滚动焦点。
17. 作为听众，我希望更厚的进度条能准确拖动，以便调整播放位置。
18. 作为听众，我希望换歌后进度归零，停止后保留位置，以便符合预期地控制播放。
19. 作为听众，我希望换页后音乐继续，以免阅读其他专题时中断。
20. 作为维护者，我希望后续通过配置提供歌曲和封面，以便独立更新歌单。
21. 作为访客，我希望缺少音频时有真实状态，以免误认为音乐已经开始播放。
22. 作为学习者，我希望阅读到解答底部即可收起，以免返回顶部寻找按钮。
23. 作为学习者，我希望收起入口复用分隔线，以免增加页面高度。
24. 作为键盘用户，我希望分隔线也能聚焦并收起，以便不依赖鼠标。
25. 作为学习者，我希望收起后回到本题入口，以免丢失阅读位置。
26. 作为学习者，我希望双击状态栏切换示例，以便集中在当前卡片操作。
27. 作为学习者，我希望切换示例只发生一次且同步归零，以免看到混合的执行状态。
28. 作为键盘用户，我希望 Shift+Tab 恢复正常导航，以免焦点移动时误切样本。
29. 作为学习者，我希望代码区域的双击最大化继续可用，以便查看完整代码。
30. 作为学习者，我希望单步时动画外框不跳动，以便连续观察执行过程。
31. 作为学习者，我希望格子和节点大小稳定，以便比较变化。
32. 作为学习者，我希望必要的算法移动仍清楚展示，以便理解实际行为。
33. 作为学习者，我希望前后步进和拖动时恢复同一真实状态，以免布局修复改变算法展示。
34. 作为窄屏用户，我希望内容不被挤成难读的小图，以便看清当前操作。
35. 作为减少动态效果的用户，我希望装饰动效可减弱，以便舒适阅读。
36. 作为博客维护者，我希望多个题卡独立工作，以免一个操作影响其他题目。

## Implementation Decisions｜实现决策

- 复用现有内容加载和筛选边界，使文章隐藏规则在所有输出入口一致生效；单纯修改首页列表不能满足范围。
- 音乐参考 Firefly 的单一音频管理思路，拆开播放器状态、歌单配置与显示界面；使用现有博客导航和主题体系接入。
- 音频状态是图标、进度及曲目高亮的来源；不以点击按钮后的乐观状态代替音频实际事件。
- 音频实例与文章页面生命周期解耦，确保换页继续；监听器、浮窗和异步播放操作需避免重复挂载及失效更新。
- 最终 C 的视觉选择作为设计基准，重新实现正式组件；不直接将累积的原型覆盖样式作为正式架构。
- 分隔线与所属题卡建立明确的展开状态及收起动作联系，不通过全页点击或当前可见卡片推断所属关系。
- 状态栏通过现有样本切换入口触发轨迹重建及归零，避免并行维护第二套状态。
- 布局稳定能力放在共享渲染器和公共动画容器中；题目模块提供当前样本及其展示边界所需的结构信息。
- 布局边界优先由样本、轨迹与结构元数据计算或缓存；不能在每次单步时遍历全部 DOM 或重新播放轨迹测量。
- 固定结构锚点、单元尺寸、标记占位和样本最大边界，并继续使用当前快照渲染实际状态。
- 不新增数据服务、数据库或外部音乐接口。歌曲使用配置资源，来源后续由用户提供。
- 原型选择代码、切换栏及演示状态不进入正式用户界面。
- 算法进度栏永久保持现有布局、样式、按钮顺序和交互，只允许上一步、下一步及拖动进度条。

## Testing Decisions｜测试与验收

验收范围已由用户确认：以浏览器可见行为为主，覆盖文章隐藏、音乐交互、分隔线收起、双击切样本和动画尺寸稳定，并复用现有算法轨迹测试。

测试关注用户可观察的行为，不要求特定 DOM 拼装过程、内部缓存形式或某个原型像素值。尽量复用既有内容入口、公共卡片事件和浏览器页面，不为本任务额外引入测试框架。

| 验收对象 | 通过条件 |
| --- | --- |
| 文章展示 | 17 篇专题继续可访问；其他文章保留源码但不在首页、归档、搜索、分类、标签、订阅与站点地图出现 |
| 隐藏详情 | 隐藏文章详情不继续公开正文，开发与构建输出一致 |
| 音乐视觉 | 顶栏位置正确；小巧融合封面；左文字上下排列；右仅歌名；无播放小点和时长占位符 |
| 音乐交互 | 悬停和浮窗内移动不会误关闭；点击歌曲同步当前信息并归零；首尾曲目可浏览和选择 |
| 音乐真实状态 | 接入有效音频后验证开始、停止、续播、拖动、结束和失败状态；缺少音频不可报告完整播放验收通过 |
| 音乐换页 | 当前曲目、位置和播放状态不因内部导航清空；无重复音频实例 |
| 分隔线 | 展开时悬停或聚焦变细，点击及键盘均收起所属卡片；布局不跳动；收起后恢复普通分隔线 |
| 样本切换 | 一次双击只切换一次，单击不切换；切换归零；示例输入、变量、输出、说明和代码高亮同步 |
| 键盘 | Shift+Tab 正常导航，Enter／空格可切样本；代码双击最大化继续工作 |
| 动画外框 | 同一样本同视口检查初始、增长、分支、结束、回退及拖动，外框高度保持一致，允许测量约 1px 的舍入误差 |
| 动画内部 | 格子、标签和字体不因步骤内容无关变形；结构锚点稳定，必要算法运动保留 |
| 算法行为 | 原有算法输出、不可变快照、语言高亮映射及最终返回结果继续正确 |
| 进度栏 | 仍只有上一步、下一步与进度条；布局、样式、顺序及交互无变化 |
| 多卡片与导航 | 同页多个展开卡片各自独立；离开再返回没有重复监听或陈旧状态 |
| 主题与窄屏 | 深浅主题、主题色、窄屏及减少动态效果设置下可读、可操作，不溢出视口 |

既有测试先例包括公共终端输入输出测试、卡片挂载生命周期测试、算法及轨迹快照测试、矩阵和递归结构测试。新增回归用例应验证双击只触发一次、正常焦点导航、多卡片归属和布局边界，而非复制实现代码。

动画浏览器检查以杨辉三角为已复现起点，再按共享渲染器选择数组／一维 DP、矩阵／二维 DP、树、链表、图、回溯、堆及 Trie 的代表题；应覆盖结构增长、标签变化和边界样本。所有实际检查及未覆盖范围必须记录。

实现后的必要项目检查包括算法与轨迹回归、静态检查、生产构建以及差异检查；构建成功不能替代浏览器验收。

## Out of Scope｜不在本次范围

- 修改默认主题色，覆盖访客现有颜色选择。
